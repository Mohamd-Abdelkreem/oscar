# P02 HTTP Contract

**Status:** Proposed P02 behavior, not implementation evidence. Existing paths below are verified against current routes; rows marked **new** require implementation. Read with the [specification](../spec.md), [research](../research.md) and [operations contract](operations.md).

## Shared protocol

Paths are relative to `API_PREFIX` (current default `/api/v1`). Preserve `ResponseHelper`: success contains `success: true`, `statusCode`, `message`, `data`, `requestId`, `timestamp`, `path`; errors contain `success: false`, `statusCode`, `code`, `message`, optional field `errors`, and the same request metadata. Production errors exclude stacks and private payloads.

Login/refresh success remains `data: { user, tokens: { accessToken } }`. Only the intended session receives the access credential. Set HttpOnly `refreshToken` at `${API_PREFIX}/auth` and readable `csrfToken` at `/`; keep production Secure, SameSite=lax and existing remember-me cookie behavior. Do not include refresh tokens in JSON. Authenticated unsafe methods require matching `x-csrf-token` and CSRF cookie. Refresh requires CSRF when its refresh cookie is present. Public credential actions require their action credential, not a logged-in session.

Bearer middleware checks current verified ACTIVE account and its owned, unrevoked, unexpired stable session. Signed role alone grants no authority. Mutations repeat actor/session/target checks under transaction locks. Reset, password change, logout-all and full denial revoke affected sessions before returning; single logout derives the stable session from authenticated context rather than a stale cookie hash.

Read-only token validation and HEAD requests consume no credential and grant no session. Explicit POST/PATCH actions alone change state. Evaluate exclusive expiry after locks: `now >= expiresAt` is invalid; JWT clock tolerance cannot extend stored session/action expiry. Credential/account responses use `Cache-Control: no-store`; action tokens stay out of logs, error paths and account projections.

## Request and projection rules

All bodies/query objects use strict shared schemas; reject unsupported fields. Retain normalized trimmed lowercase email (maximum 320), fullName (nonblank, maximum 150), nullable phone (maximum 30) and password length 15–128. Login/current-password input remains 1–128. Matching `passwordConfirmation` is required only for reset, change and invitation acceptance; registration retains its existing password-only body plus optional referralCode and rejects an unsupported confirmation field. Protected bootstrap stdin also uses a single password. Reset/change reject an unchanged password.

Proposed shared token-query bound is 1-4096 characters, preserving the current minimum and adding a finite maximum for affected credential endpoints. This is a P02 design choice and needs schema boundary tests.

- Registration gains optional `referralCode`: trim, lowercase, treat blank as absent, then require exactly 32 hexadecimal characters. Resolve an existing USER; an invalid/nonemployee/self reference is rejected. It does not accept `sponsorUserId`, `role`, status, balances or verification fields.
- Versioned account controls require `confirmed: true`, nonblank reason bounded to 500 characters, and nonnegative integer `expectedVersion` matching `accountVersion`. A winning status/restriction transition increments the version once, including public pending-to-active email activation. Earlier confirmed intent becomes stale after activation. Stale or unchanged intent returns 409 CONFLICT after live authority/version checks, with no mutation/version increment/material audit.
- Invitation issue requires `fullName`, normalized `email`, `confirmed: true`, and the same reason rule. Reissue/revoke require positive `expectedVersion` matching `tokenVersion`, confirmation and reason. Actor, time, outcome and audit snapshots are server-derived.
- Own safe user extends the existing id/name/email/phone/role/status/verification/creation/update projection with required `referralCode` (own employee code; null for ADMIN), `tasksBlocked`, `withdrawalsBlocked`, `accountVersion`. It excludes sponsor-account private data, hashes, session IDs, action credentials, signing/provider keys and provider payloads.
- Employee-control projection contains only id, status, tasksBlocked, withdrawalsBlocked and accountVersion. General employee list/detail/search remains P13. Admin projection exposes identity/status/version, with no password or invented lastActiveAt. ADMIN status allows PENDING_VERIFICATION, ACTIVE, DEACTIVATED; employee status allows PENDING_VERIFICATION, ACTIVE, SUSPENDED, BANNED.
- Invitation projection allows id, email, fullName, issuerUserId, tokenVersion, issuedAt, expiresAt, acceptedAt, revokedAt, derived status and delivery status. Derive status in this order: acceptedAt → ACCEPTED; revokedAt → REVOKED; now >= expiresAt → EXPIRED; otherwise PENDING. Acceptance/revocation are mutually exclusive. Later expiry cannot relabel a terminal disposition. DeliveryStatus is independently NOT_ATTEMPTED, UNKNOWN, ACKNOWLEDGED or REJECTED. No token/link/hash/provider response is returned.

Compatibility decision: retain existing `safeUserSchema`, `authUserDataSchema`, `authSessionDataSchema`, their inferred `SafeUser`/`AuthUserData`/`AuthSessionData` types, legacy status enum and field allowlist in `account/account.schema.ts` without adding required fields. Add strict `identityUserSchema`, `identityUserDataSchema`, `identitySessionDataSchema` and inferred `IdentityUser`/`IdentityUserData`/`IdentitySessionData` in `identity/identity.schema.ts`, reusing the legacy field definitions and replacing status with the P02 role-compatible rule. All four P02 additions are required. Export both through `src/index.ts`; API DTO aliases, mapper, response validation and OpenAPI use the identity schemas exclusively after cutover. Legacy schemas remain compatibility shapes for frozen callers, not validators for enriched API responses. Current web auth/users adapters import legacy types and use typed Axios envelopes rather than those strict parsers; a full identity DTO remains structurally usable by those callers on existing eligible-account paths. P03 adopts the identity exports when integrating new fields/statuses. There is one enriched wire response, no alternate auth endpoint/envelope or optional-field fallback. Contract tests must reject a missing P02 field and preserve representative legacy fixture assignments; root type/build checks retain all frozen callers.

Lists accept existing page/limit semantics: defaults 1/25, maximum limit 100, decimal safe integers and no invalid overflow. Proposed list `data` is `{ items, pagination }`; `ResponseHelper` additionally exposes `paginationMeta` from `data.pagination`. Metadata is page, limit, total, totalPages, hasNextPage, hasPreviousPage. Order by createdAt DESC, id DESC as the unique tie-breaker. Obtain filtered page rows and total from one read-only RepeatableRead transaction with the same role/filter predicate; metadata describes that snapshot, not later pages. Use explicit projections; an unavailable database is an error, never an empty successful list.

## Authentication and own account

| Method/path                                          | Input and authority                                                          | Success and required effects                                                                                                                                                                                                                       |
| ---------------------------------------------------- | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| POST `/auth/register`                                | Existing strict registration plus optional referralCode; public source limit | 201 `{ user }` pending. Atomically create USER, fixed sponsor decision and one zero P01 wallet before email dispatch. No session or entitlement.                                                                                                   |
| **New** GET/HEAD `/auth/validate-verification-token` | Query `token`; public source/token limits                                    | 200 `{ valid: true }` for current pending verification credential; no consumption or account projection. HEAD has no body.                                                                                                                         |
| POST `/auth/verify-email`                            | Query `token`; explicit action                                               | 200 `{ user }`; consume current credential once and activate only eligible PENDING_VERIFICATION identity. No session issuance or unsuspension.                                                                                                     |
| POST `/auth/resend-verification`                     | `{ email }`; public source/account limits                                    | 200 existing neutral `{ message }`, independent of eligibility/send result. Issue or replace eligible pending credential, including null hashes after upgrade; apply retained 60-second cooldown only where prior issuance exists. Old links fail. |
| POST `/auth/login`                                   | `{ email, password, rememberMe }`                                            | 200 shared session for current eligible USER/ADMIN. Create independent stable session; no public role assignment.                                                                                                                                  |
| **New** POST `/auth/admin/login`                     | Same login body; shared source/account buckets                               | 200 shared session only for ACTIVE verified ADMIN. Wrong password, USER, missing, pending or denied account receives the same generic 401.                                                                                                         |
| POST `/auth/refresh`                                 | Refresh cookie and applicable CSRF; public bounded refresh bucket            | 200 rotated shared session. Consume current refresh credential once; retain stable session and original absolute expiry.                                                                                                                           |
| POST `/auth/logout`                                  | Current bearer session + CSRF                                                | 200 `{}`; revoke only authenticated session and its refresh credentials, clear cookies.                                                                                                                                                            |
| POST `/auth/logout-all`                              | Current bearer session + CSRF                                                | 200 `{}`; atomically revoke all account sessions/refresh credentials including caller, clear cookies.                                                                                                                                              |
| POST `/auth/forgot-password`                         | `{ email }`; public source/account limits                                    | 200 existing neutral `{ message }`; only current eligible identity receives recovery. Sending neither activates nor restores authority.                                                                                                            |
| GET/HEAD `/auth/validate-reset-token`                | Query `token`; public source/token limits                                    | 200 `{ valid: true }`; current eligible reset credential only, no consumption. HEAD has no body.                                                                                                                                                   |
| POST `/auth/reset-password`                          | Query `token`; `{ newPassword, passwordConfirmation }`                       | 200 `{ user }`; consume once, replace hash and revoke all sessions atomically; clear cookies, require fresh sign-in.                                                                                                                               |
| PATCH `/auth/change-password`                        | Bearer + CSRF; `{ currentPassword, newPassword, passwordConfirmation }`      | 200 `{ user }`; verify current hash under lock, replace password, revoke all sessions including caller and clear cookies.                                                                                                                          |
| GET `/users/me`                                      | Current bearer session                                                       | 200 `{ user }` own safe projection only.                                                                                                                                                                                                           |
| PATCH `/users/me`                                    | Bearer + CSRF; at least one of fullName/phone                                | 200 `{ user }`; only supported own profile fields change, with live authority recheck.                                                                                                                                                             |

Recovery issuance, GET/HEAD reset validation and reset consumption all require current USER or ADMIN, ACTIVE status and nonnull emailVerifiedAt. Pending/unverified/SUSPENDED/BANNED/DEACTIVATED identities fail credential validation/consumption with the same generic 401; forgot-password remains neutral. Partial controls do not deny recovery. Recheck the predicate and exact credential after locks on issuance/consumption; validation reads current persisted authority without consuming. Reset preserves role/status/verification. Change clears outstanding reset credentials with password/session changes; full denial clears verification/reset pairs, and restoration requires fresh eligible links.

Registration delivery rejection/timeout/unknown acknowledgement returns 503 `SERVICE_UNAVAILABLE` after the complete pending identity/wallet/sponsor decision commits. Use safe text explaining that a pending account may exist and verification can be requested again. Retain state; retrying registration may return 409 email-in-use. Resend/forgot return the same 200 neutral message/schema, no-store and applicable standard headers for known/unknown/ineligible accounts and provider failures under equivalent source/account limiter histories. Infrastructure failure may return the same safe 503 for every eligibility case; never use provider failure to disclose eligibility. Timing may differ with provider work; timing equalization is explicitly outside P02 and no constant-time privacy claim is made. Acknowledgement means provider API acceptance, not mailbox delivery.

## Administrator and employee controls — all new

Every `/admin/...` path requires current ACTIVE verified ADMIN bearer authority; every mutation also requires CSRF, confirmation, reason, bounded actor limits and transactional audit. UUID parameters are validated. There is no generic role/email/password/balance patch.

| Method/path                                     | Input                                                                            | Success and transaction boundary                                                                                                                                                                                                                                         |
| ----------------------------------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| GET `/admin/employees/:userId/restrictions`     | UUID                                                                             | 200 `{ employee }` containing only id/status/tasksBlocked/withdrawalsBlocked/accountVersion for an existing USER. No general employee list/detail or financial projection.                                                                                               |
| PATCH `/admin/employees/:userId/restrictions`   | Versioned controls plus at least one of status, tasksBlocked, withdrawalsBlocked | 200 `{ employee }` with the same minimal control projection; status accepts ACTIVE/SUSPENDED/BANNED. Restore to ACTIVE only when verified, otherwise PENDING_VERIFICATION. Preserve unspecified controls; full denial revokes sessions atomically. Reject ADMIN targets. |
| GET `/admin/admins`                             | page/limit                                                                       | 200 safe admin projections and pagination, role ADMIN only.                                                                                                                                                                                                              |
| GET `/admin/admins/:userId`                     | UUID                                                                             | 200 `{ admin }`, existing ADMIN only.                                                                                                                                                                                                                                    |
| PATCH `/admin/admins/:userId/status`            | Versioned controls and status ACTIVE/DEACTIVATED                                 | 200 `{ admin }`; ACTIVE requires verified identity. DEACTIVATED revokes sessions and outstanding issued invitations. Guard serializes all admin-population changes; reject self-denial and loss of last eligible admin.                                                  |
| GET `/admin/invitations`                        | page/limit                                                                       | 200 safe invitation projections and pagination. Expiry is derived without a worker.                                                                                                                                                                                      |
| GET `/admin/invitations/:invitationId`          | UUID                                                                             | 200 `{ invitation }`; current generation and truthful safe delivery state.                                                                                                                                                                                               |
| POST `/admin/invitations`                       | Invitation issue body                                                            | 201 `{ invitation }` after bounded provider acknowledgement; only unused email. Commit generation/audit first; a failed or uncertain send returns 503 and retains pending intent. Existing intent requires explicit reissue, not silent overwrite.                       |
| POST `/admin/invitations/:invitationId/reissue` | Generation-guarded controls                                                      | 200 `{ invitation }` after acknowledgement; fresh generation/issuer/expiry invalidates older links. Accepted intent is terminal. Failed/unknown send returns 503 with replacement retained.                                                                              |
| POST `/admin/invitations/:invitationId/revoke`  | Generation-guarded controls                                                      | 200 `{ invitation }`; revoke outstanding generation and commit audit. Accepted, stale or already closed commands conflict.                                                                                                                                               |

Restrictions preserve wallets, sponsor identity and financial history. Partial task/withdrawal blocks retain eligible login and do not claim downstream workflow enforcement. ADMIN lifecycle targets verified ACTIVE/DEACTIVATED identities only; denying already-provisioned pending membership or its verification authority is excluded. Invitation revocation before acceptance remains supported. Invitation reissue retains the original fullName; it provides no profile-edit capability. Issuer restoration never revives revoked invitation credentials. Neither privileged reads nor bootstrap bypass admin guards. Issue/reissue after dispatch returns the freshly read current-generation disposition, including ACCEPTED/REVOKED/EXPIRED after acknowledgement; a superseded generation returns 409 CONFLICT. Definite/uncertain delivery failure returns 503 and retains state. See [dispatch race rules](operations.md#resend-boundary-and-failure-semantics).

## Invitation recipient — new public credential paths

| Method/path                                | Input                                                                              | Result                                                                                                                                                                                                                                                         |
| ------------------------------------------ | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET/HEAD `/auth/validate-admin-invitation` | Query `token`; public source/token limits                                          | 200 `{ valid: true }` only for current unexpired unconsumed generation and currently eligible issuer. No account creation or consumption; HEAD has no body.                                                                                                    |
| POST `/auth/admin-invitations/accept`      | Query `token`; `{ newPassword, passwordConfirmation }`; public source/token limits | 201 `{ user }` ACTIVE verified ADMIN after proof of invited email, issuer/unused-email rechecks and single-use acceptance/audit commit. Do not issue a session; sign in through admin entry. Recipient supplies no admin reason/actor/fullName/email override. |

`ADMIN_INVITATION` is a distinct JWT purpose bound to invitation id/generation/email with issuer/audience/expiry validation and stored hash equality. Replaced, revoked, expired, replayed or issuer-denied credentials grant zero transitions. An email already owned by any account is a conflict; never promote an employee or replace an existing account password.

## Failures and verification ownership

| HTTP/code                 | Consumer behavior                                                                                                                                      |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 400 `VALIDATION_ERROR`    | Malformed/unsupported schema input; existing `ValidationException` preserves bounded field errors without credential values.                           |
| 400 `BAD_REQUEST`         | Semantically invalid referral or invalid verification/invitation credential; safe action denial.                                                       |
| 401 `UNAUTHORIZED`        | Missing/invalid/revoked session, generic admin credentials, invalid reset credential; require fresh eligible sign-in or fresh action link.             |
| 403 `FORBIDDEN`           | Valid caller lacks ADMIN authority or CSRF fails; no read/mutation.                                                                                    |
| 404 `NOT_FOUND`           | Privileged role-filtered target does not exist; no fabricated record.                                                                                  |
| 409 `CONFLICT`            | Duplicate identity, stale version, invalid lifecycle/self/last-admin transition or unavailable invitation state; reread before a new explicit command. |
| 429 `RATE_LIMIT_EXCEEDED` | Bounded limiter rejection with installed standard headers; wait before retrying.                                                                       |
| 503 `SERVICE_UNAVAILABLE` | Provider unavailable/uncertain with retained pending state, or unavailable infrastructure; no claim of activation/delivery.                            |
