# P03 Data Model and Client State

**Status**: Design only. Existing P02 wire/persistence entities are reused; P03 creates no database model or migration. Server mutations retain their current transactional, single-use/version and audit owners. Browser state cannot grant identity, role, entitlement or financial authority.

## Existing Wire Entities

Definitions remain in `packages/contracts/src/`; use inferred types rather than duplicate frontend business schemas.

| Entity/schema                                    | Fields and relationships                                                                                                                                                   | Validation/authority                                                                                                                                                                                                                                                                            |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Current account / identityUserSchema             | id, fullName, email, nullable phone, role, status, nullable emailVerifiedAt, createdAt, updatedAt, nullable referralCode, tasksBlocked, withdrawalsBlocked, accountVersion | Strict safe-user extension. USER status: PENDING_VERIFICATION/ACTIVE/SUSPENDED/BANNED; ADMIN: PENDING_VERIFICATION/ACTIVE/DEACTIVATED. ADMIN has null referralCode and false partial restrictions. Protected use requires ACTIVE plus verified email and current server session.                |
| Session response / identitySessionDataSchema     | user: current account; tokens: accessToken                                                                                                                                 | Strict data object. Access token enters the existing memory store only after full parsing/current-scope checks. Do not cache the token-bearing response. Session identifier/refresh authority remain server/cookie owned and are not new public DTO fields.                                     |
| Account response / identityUserDataSchema        | user: current account                                                                                                                                                      | Registration, current account, verification, reset/change and invitation acceptance use this safe projection. Registration creates pending employee and fixed sponsor decision; acceptance creates verified admin without auto-session.                                                         |
| Administrator / adminSchema                      | Safe account fields with role ADMIN, admin status and accountVersion                                                                                                       | Strict output differs from IdentityUser: referral/partial restriction fields are absent. Never coerce fixtures or unknown status into active/inactive.                                                                                                                                          |
| Administrator invitation / adminInvitationSchema | id, email, fullName, issuerUserId, tokenVersion, issuedAt, expiresAt, nullable acceptedAt/revokedAt, status, deliveryStatus                                                | Issuer relates to server admin. tokenVersion ≥1. PENDING/ACCEPTED/REVOKED/EXPIRED disposition comes from server expiry/terminal evidence. Delivery is separate NOT_ATTEMPTED/UNKNOWN/ACKNOWLEDGED/REJECTED evidence. No raw credential/hash/password/provider payload/audit reason is returned. |
| Bounded admin/invitation list                    | items of corresponding entity; pagination                                                                                                                                  | page, limit, total, totalPages, hasNextPage, hasPreviousPage. Defaults 1/25; request limit ≤100. data.pagination and optional matching envelope paginationMeta cannot disagree. Zero total means zero pages; out-of-range page is not a command failure or proof of global emptiness.           |

Names/reasons are nonblank and reject null characters, maximum 150/500 respectively. accountVersion is integer 0–2147483647; invitation versions start at 1. Email normalization is shared trim/lowercase; passwords are never trimmed/normalized. Existing login permits 1–128 characters and requires rememberMe; approved UI submits false. New passwords require 15–128 plus matching confirmation; change also requires a different password and server current-password check.

Blank optional referral means absent; shared preprocessing trims/lowercases valid 32-character lowercase hexadecimal codes. Client password confirmation is not an extra registration wire field. Client role/sponsor reassignment/financial authority are never accepted.

## Existing Server Transitions Consumed by P03

| Entity/action           | Allowed effect                                                                                                        | Browser implication                                                                                                                                            |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Employee registration   | New pending USER; fixed sponsor; wallet initialization remains existing P02 behavior                                  | Inbox/pending only; no session, available balance or paid entitlement. Provider failure may follow persistence; no automatic registration replay.              |
| Verification            | Current valid credential explicitly consumed once; pending becomes active                                             | Preview/reload has no effect. Success only after validated committed action; exact server expiry wins.                                                         |
| Session                 | Login creates permitted session; refresh rotates existing authority; ordinary logout revokes current session          | Multiple devices remain permitted. Current role/status/session rechecked independently on each server request.                                                 |
| Reset/change/logout-all | Revoke target account's prior sessions; reset/change set valid new password                                           | Fresh sign-in required. Reset clears browser cookies even when a different account is signed in, but does not revoke that unrelated account's server sessions. |
| Invitation issue        | Pending intent/version plus distinct delivery evidence                                                                | Not an immediately active account. Provider failure/lost reply may follow intent commitment.                                                                   |
| Reissue                 | Current eligible unaccepted invitation, cooldown/version checks; new tokenVersion/current issuer and delivery attempt | Previous token invalid. Revoked/expired invitations may be eligible; browser may not infer eligibility from its clock alone.                                   |
| Revoke                  | Outstanding PENDING/current version becomes revoked                                                                   | Acceptance denied; generation need not increment.                                                                                                              |
| Accept                  | Explicit password, valid purpose/address/current generation/expiry/issuer; one verified ADMIN created                 | No cookie/session created; separate dedicated sign-in. Collision never promotes an existing account.                                                           |
| Admin status            | Confirmed reason/current version; active↔deactivated subject to self/last-admin/pending-target checks                 | Deactivation revokes sessions/outstanding issued invitations. Reactivation does not revive sessions.                                                           |

At now >= expiresAt a credential/invitation is expired. Server exact boundaries/state transactions remain P02 owners; no client calendar replaces them. Invalidating a credential after an uncertain response does not itself prove the requested action committed.

## Proposed Browser State

Account/credential state stays inside browser lifecycle/hooks, not persistence, financial fixtures or a new global business store. The sole storage exception is the nonsecret cookie-write barrier below; it holds no account authority or request payload.

| Owner/state          | Fields                                                                                                              | Lifetime/invariants                                                                                                                                                                                                                                                                                                                                         |
| -------------------- | ------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Session runtime      | Non-secret epoch, authority-check generation, allowed validated account scope, refresh/cookie command pending state | One existing token owner. Epoch retires before replacement work; completion must match epoch/check generation. No password/token in keys, metadata or messages. Never shared mutable account state during SSR.                                                                                                                                              |
| Authority view       | checking / allowed / anonymous / restricted / wrong-role / unavailable                                              | Allowed requires latest validated server check. Path/check change blocks before protected children mount. Unavailable/contract failure is not anonymity. A policy/CSRF 403 triggers reconciliation, not assumed global revocation.                                                                                                                          |
| Credential flow      | Opaque local flow id, action purpose, transient credential/input, safe preview/command outcome                      | missing/checking/ready/invalid/submitting/committed/uncertain/error. Opening only previews. Clear at completion/dismissal/teardown; live correction input may survive a recoverable denial in the active form.                                                                                                                                              |
| Command guard        | Non-secret scope/operation/target/version, pending/uncertain marker                                                 | Outlives dismissible dialog; rejects double submit/remount. No retained credential payload or Mutation variables; no automatic uncertain replay.                                                                                                                                                                                                            |
| Cookie-write barrier | Strict version:1, opaque operationId, state:pending/uncertain; one fixed localStorage key                           | Read/write only under the same exclusive Web Lock. Synchronously write/read back before HTTP dispatch. No identity, token/hash, session ID, password, payload, URL or timestamp/TTL. Matching live request owner alone removes it after a complete terminal HTTP response; inherited/invalid/unreadable state blocks private restoration and cookie writes. |
| Admin list/detail    | Account/epoch-scoped query keys, independent page/limit, validated DTOs                                             | No global page-local filtering/count substitute. Refresh preserves unrelated dirty safe drafts; stale results cannot overwrite newer target/version/authority.                                                                                                                                                                                              |

Teardown order: block private render/handlers; retire epoch/check; coordinate cookie writes; cancel scoped reads; clear private Query/command/error/form state and current memory token; discard old completions; only then admit permitted replacement work after cookie ordering is resolved and current authority checked. Do not erase the cookie-write barrier with private cache/form cleanup or generic finally/error handling. The original observer outlives component dismissal and UI deadlines. Owner loss leaves the barrier pending/uncertain across reloads/tabs; no other owner, timeout or authority read clears it. Recovery uses a wholly isolated cookie/storage context and fresh explicit sign-in without claiming the abandoned server action's result. The [session contract](contracts/ui-session.md#cookie-write-barrier-and-owner-loss-u1) specifies release evidence and storage/topology limits. Nonsecret messages invalidate/revalidate, never grant authority.

No subscription/wallet/destination value belongs to this model. C3's unavailable presentation is view state, never zero/Free/empty-address data or financial entitlement.
