## Validation Scenarios and Expected Outcomes

1. **Configuration/import/isolation**: Start each process with its separately scoped test config/DB role and inspect public app/router import without signer files/secrets mounted. Missing/mismatched network/genesis/token/credential/recovery/resource settings prevent protected work. API/worker cannot read/decrypt signer data or alter signing authority; signer never opens public HTTP. Linux nonowner access is denied. Sentinel secrets never appear in responses, logs, errors, browser artifacts or test reports. Versioned TronWeb ESM/sign/build behavior passes under Node24.

2. **Concurrent provisioning and fresh-host loss**: Request one employee address from separate authenticated clients while another employee provisions. Interrupt before/after local encryption, remote durable write, ACK and READY commit; lose replies and restart. Assert one independent binding per employee/network, different addresses, no public address before ACK and exact same address on retry. Delete only disposable primary custody storage; restore the newly published key/binding from independent recovery using separately escrowed test decryption authority, including records absent from the older DB snapshot. Tamper/missing ACK/key/history stays fenced/nonready. No ownership reuse follows account restrictions.

3. **Verification/exactness/replay/races**: Feed successful solidified configured-token transfer of 1.000001 to assigned recipient, then 100 repeats and simultaneous separate-client verification. Assert one receipt/operation/audit and exact NON_REFERRAL available source increase. Two eligible raw logs in one transaction yield two receipts/credits with original array indices. Wrong token/network/recipient, symbol forgery, failed/unfinalized/disappearing/conflicting/malformed data, zero/uint256 overflow and total-wallet overflow produce no unauthorized/partial credit. Concurrent purchase/grant/credit preserves source/reserved totals and existing financial invariants. Force real service failure after a dependent write and inspect complete rollback.

4. **Calendar/lifecycle**: With fixed clocks and retained assignments, verify Saturday/Sunday, closed task window, Free/expired/withdraw-blocked/banned employee deposits still qualify exactly once. This does not reactivate login, change subscription or authorize withdrawal. Account history/assignment remains retained and never reassigned.

5. **Resumable detection**: Use multiple pages, repeated fingerprints, equal timestamp boundaries, host clock ahead/behind chain time, transient cursor expiry, delayed events older than hot overlap, out-of-order results and outage/throttling. The pre-generation solidified chain floor must still include every transfer. Crash before/after candidate/checkpoint/financial commit and restart overlapping workers. Assert durable pending work, same-window retries, recurring history and no missed/extra receipt. Provider failure never becomes successful empty scan; missing historical coverage remains a gate.

6. **Authorized history and manual grants**: Read >one page for employee/admin filters and deterministic ties, comparing rows/counts/safe projections. Try cross-user/stale/revoked/wrong-role/CSRF/forged-field requests. Create first grant on empty wallet with meaningful external reference, then valid same-wallet reference. Assert one CREDIT/ADMIN_ADJUSTMENT/NON_REFERRAL effect/audit and no chain receipt, reserved/referral relabeling or correction mutation. Repeat same action/key and new key, race clients, lose response and GET original action. Changed actor/amount/target/reason/reference or reused request key for another action conflicts; no silent new actionId is generated after uncertainty.

7. **Fixed treasury/attempt recovery**: Create a protected intent with recovered source/funds/resources. Reject changed destination/network/token/amount, unsigned tamper, unauthorized process and excess/failed resource estimate. Competing intents for the same source/network/token cannot both dispatch; distinct sources are not subject to this mutual exclusion. Crash after local signed-envelope persistence but before DB TxID/digest, lose remote/broadcast ACK and restore DB missing sweep metadata; recover identical signed object plus complete immutable intent/claim before any rebuild. Expired/not-found/contradictory evidence without complete nonexecution proof remains UNKNOWN/active. Canonical success records exact treasury movement; canonical REVERT/OUT_OF_ENERGY yields CHAIN_FAILED with zero intended movement and recorded costs. Solidified balance reads ignore head-only movement. Wallet/receipt count is unchanged; no automatic top-up/replacement/payout occurs.

8. **Pause/fence/restart**: Race mutation/exclusive restore admission with independent barriers; active work drains, later purchase/reward/deposit/grant writes fence, stale Serializable snapshot cannot bypass it and reads/reconciliation continue. The proposed `recoverOperation()` remains read-only for every call. Recover an existing ledger operation using a new request key while the restore fence or boot admission is closed: validate existing identity/outcome, return that outcome and leave request-key aliases unchanged. Only financially admitted `execute()`/`runInTransaction()` replay may bind a new alias. Pause blocks later initial/rebroadcast admissions; work with durable broadcast-intent admission before the pause may finish sending and remains possibly sent until reconciled. Confirmations/reconciliation continue during pause and weekends. Start an actual API process against stale OPEN without running protected admission tooling: its fresh boot UUID must remain unable to mutate finance. Tool acknowledgement/current generation admits only that boot; generation change invalidates old acknowledgements. Missing post-snapshot off-chain history stays fenced despite complete rescan. Shutdown closes resources and resumes the same provisioning/attempt records. Full deployed WAL/PITR stays P11.

9. **Real controlled testnet**: With complete separately authorized inputs, execute actual provisioning/fresh key recovery, inbound test token deposit and fixed treasury sweep journeys. Record public address/TxIDs/raw log identities/exact amounts, solidified success, company resource costs and recovered attempt outcomes. Testnet assertions use real provider/independent-host evidence; network doubles do not pass this gate. Mainnet resolution/missing funding/recovery/provider access fails closed and leaves the phase incomplete.
